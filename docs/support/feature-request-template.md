# Feature Request Template

```
## Feature
<One sentence describing what you'd like Occountant to do.>

## Problem it solves
<What are you trying to accomplish today, and why is it hard/impossible now?>

## Who benefits
<Just you? A type of business (café, retailer, clinic…)? Everyone?>

## How important is it to you?
Nice-to-have / Would use often / Blocking my adoption

## Current workaround
<How you handle this today, if at all.>

## Notes
<Examples, similar tools, mockups, edge cases.>
```

## How we evaluate requests

We weigh feature requests against Occountant's core promise: **correct, private, recoverable books
for small businesses.** A request is more likely to land when it:

- serves a clear small-business need shared by many customers,
- fits the offline-first, single-user model (or has a clean path within it),
- does **not** compromise data integrity, determinism, or privacy.

Requests that would require networked multi-user access, cloud dependence, or changes to the
accounting engine are weighed carefully and, if accepted, planned as major work. See the roadmap in
the GA review.
